# MCP SDK 2.0.0 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the `milkman-mcp` plugin from MCP Java SDK 0.17.0 to 2.0.0, targeting the 2025-11-25 MCP protocol specification.

**Architecture:** Two files change: `pom.xml` (BOM version bump + dependency swap from `mcp` to `mcp-json-jackson2`) and `McpRequestProcessor.java` (replace removed `customizeRequest()` with `httpRequestCustomizer()`). Everything else is source-compatible with 2.0.0.

**Tech Stack:** Java 21, Maven, `io.modelcontextprotocol.sdk:mcp-bom:2.0.0`, `io.modelcontextprotocol.sdk:mcp-json-jackson2:2.0.0`

## Global Constraints

- Module: `milkman-mcp` only — do not touch other modules
- Java version: 21 (Temurin) via SDKMAN — always prefix Maven commands with `source ~/.sdkman/bin/sdkman-init.sh && sdk use java 21-tem &&`
- Jackson: milkman uses Jackson 2.x throughout; use `mcp-json-jackson2`, never `mcp-json-jackson3` or the `mcp` umbrella artifact
- `reactor-core` exclusion must be retained — milkman manages its own reactor version
- No new features, no refactoring beyond what the migration requires

### Task 1: Update `pom.xml` — BOM version and dependency swap

**Files:**
- Modify: `milkman-mcp/pom.xml`

**Interfaces:**
- Produces: `mcp-json-jackson2:2.0.0` on the compile classpath (replaces `mcp:0.17.0`)

- [ ] **Step 1: Update the BOM version**

In `milkman-mcp/pom.xml`, inside `<dependencyManagement>`, change the BOM version from `0.17.0` to `2.0.0`:

```xml
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp-bom</artifactId>
    <version>2.0.0</version>
    <type>pom</type>
    <scope>import</scope>
</dependency>
```

- [ ] **Step 2: Swap the MCP dependency**

Replace the existing `mcp` dependency (with its two exclusions) with `mcp-json-jackson2` (keeping only the `reactor-core` exclusion):

Remove this block:
```xml
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp</artifactId>
    <exclusions>
        <exclusion>
            <artifactId>jackson-databind</artifactId>
            <groupId>com.fasterxml.jackson.core</groupId>
        </exclusion>
        <exclusion>
            <artifactId>reactor-core</artifactId>
            <groupId>io.projectreactor</groupId>
        </exclusion>
    </exclusions>
</dependency>
```

Add in its place:
```xml
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp-json-jackson2</artifactId>
    <exclusions>
        <exclusion>
            <artifactId>reactor-core</artifactId>
            <groupId>io.projectreactor</groupId>
        </exclusion>
    </exclusions>
</dependency>
```

- [ ] **Step 3: Verify the module compiles (dependency resolution only)**

```bash
source ~/.sdkman/bin/sdkman-init.sh && sdk use java 21-tem && ./mvnw -pl milkman-mcp dependency:resolve -q
```

Expected: exits 0 with no errors. If you see `mcp-json-jackson2:2.0.0` resolved, you're good. A compile error here means a missing import — that's fixed in Task 2.

- [ ] **Step 4: Commit**

```bash
git add milkman-mcp/pom.xml
git commit -m "build(mcp): bump mcp-bom to 2.0.0, switch to mcp-json-jackson2"
```

### Task 2: Fix removed `customizeRequest()` in `McpRequestProcessor.java`

**Files:**
- Modify: `milkman-mcp/src/main/java/milkman/plugin/mcp/McpRequestProcessor.java`

**Interfaces:**
- Consumes: `io.modelcontextprotocol.client.transport.HttpClientSseClientTransport`, `io.modelcontextprotocol.client.transport.HttpClientStreamableHttpTransport` (both from `mcp-json-jackson2:2.0.0` transitive)
- Produces: a compiling `McpRequestProcessor` that adds request headers via the new `httpRequestCustomizer` API

- [ ] **Step 1: Remove the `addHeaders` consumer variable and its unused import**

In `McpRequestProcessor.java`, find the `connect()` method. Remove these lines (around lines 66–68):

```java
Consumer<HttpRequest.Builder> addHeaders = httpRequest -> {
  headerMap.forEach(httpRequest::header);
};
```

Also remove the import `java.util.function.Consumer` if it is no longer used elsewhere in the file (check — it is only used for `addHeaders`).

- [ ] **Step 2: Fix the SSE transport builder call**

Replace:
```java
case Sse -> HttpClientSseClientTransport
    .builder(getBaseUri(url))
    .sseEndpoint(getEndpointFromUrl(url))
    .customizeRequest(addHeaders)
    .build();
```

With:
```java
case Sse -> HttpClientSseClientTransport
    .builder(getBaseUri(url))
    .sseEndpoint(getEndpointFromUrl(url))
    .httpRequestCustomizer((req, method, uri, body, ctx) -> headerMap.forEach(req::header))
    .build();
```

- [ ] **Step 3: Fix the StreamableHttp transport builder call**

Replace:
```java
case StreamableHttp -> HttpClientStreamableHttpTransport
    .builder(getBaseUri(url))
    .endpoint(getEndpointFromUrl(url))
    .customizeRequest(addHeaders)
    .build();
```

With:
```java
case StreamableHttp -> HttpClientStreamableHttpTransport
    .builder(getBaseUri(url))
    .endpoint(getEndpointFromUrl(url))
    .httpRequestCustomizer((req, method, uri, body, ctx) -> headerMap.forEach(req::header))
    .build();
```

- [ ] **Step 4: Build the module**

```bash
source ~/.sdkman/bin/sdkman-init.sh && sdk use java 21-tem && ./mvnw -pl milkman-mcp package -DexcludedGroups=ui -q
```

Expected: BUILD SUCCESS with no compilation errors or warnings about removed APIs.
