# MCP SDK 2.0.0 Upgrade — Design

**Date:** 2026-08-04  
**Scope:** `milkman-mcp` module only  
**Target:** `io.modelcontextprotocol.sdk:mcp-bom` 0.17.0 → 2.0.0 (2025-11-25 MCP spec)

---

## Goal

Update the `milkman-mcp` plugin to use the latest MCP Java SDK (2.0.0), gaining support for the 2025-11-25 MCP protocol specification and all protocol negotiation improvements that come with it.

---

## Scope of Changes

### 1. `milkman-mcp/pom.xml`

**BOM version bump:**
```xml
<version>0.17.0</version>  →  <version>2.0.0</version>
```

**Dependency swap — `mcp` → `mcp-json-jackson2`:**

In 2.0.0 the `mcp` umbrella artifact depends on `mcp-json-jackson3` (Jackson 3.x). Milkman uses Jackson 2.x throughout, so we switch to the `mcp-json-jackson2` compatibility artifact instead. It transitively pulls in `mcp-core`, so it replaces the current `mcp` dependency entirely.

Before:
```xml
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp</artifactId>
    <exclusions>
        <exclusion>
            <artifactId>jackson-databind</artifactId>
            <groupId>com.fasterxml.jackson.core</groupId>
        </exclusion>
        <exclusion>
            <artifactId>reactor-core</artifactId>
            <groupId>io.projectreactor</groupId>
        </exclusion>
    </exclusions>
</dependency>
```

After:
```xml
<dependency>
    <groupId>io.modelcontextprotocol.sdk</groupId>
    <artifactId>mcp-json-jackson2</artifactId>
    <exclusions>
        <exclusion>
            <artifactId>reactor-core</artifactId>
            <groupId>io.projectreactor</groupId>
        </exclusion>
    </exclusions>
</dependency>
```

The `reactor-core` exclusion is retained because milkman manages its own reactor version. The `jackson-databind` exclusion is no longer needed — `mcp-json-jackson2` pulls the correct Jackson 2.x databind.

### 2. `McpRequestProcessor.java` — transport builder API fix

`customizeRequest(Consumer<HttpRequest.Builder>)` was removed in 2.0.0. The replacement is `httpRequestCustomizer(McpSyncHttpClientRequestCustomizer)`.

The new API uses `McpSyncHttpClientRequestCustomizer`, a `void` functional interface with signature `customize(HttpRequest.Builder, String method, URI endpoint, String body, McpTransportContext context)`.

**SSE transport (line 74–77):**
```java
// Before
HttpClientSseClientTransport.builder(getBaseUri(url))
    .sseEndpoint(getEndpointFromUrl(url))
    .customizeRequest(addHeaders)
    .build();

// After
HttpClientSseClientTransport.builder(getBaseUri(url))
    .sseEndpoint(getEndpointFromUrl(url))
    .httpRequestCustomizer((req, method, uri, body, ctx) -> headerMap.forEach(req::header))
    .build();
```

**StreamableHttp transport (line 78–81):**
```java
// Before
HttpClientStreamableHttpTransport.builder(getBaseUri(url))
    .endpoint(getEndpointFromUrl(url))
    .customizeRequest(addHeaders)
    .build();

// After
HttpClientStreamableHttpTransport.builder(getBaseUri(url))
    .endpoint(getEndpointFromUrl(url))
    .httpRequestCustomizer((req, method, uri, body, ctx) -> headerMap.forEach(req::header))
    .build();
```

The `Consumer<HttpRequest.Builder> addHeaders` local variable and the `addHeaders` import can be removed. Add import for `io.modelcontextprotocol.client.transport.customizer.McpSyncHttpClientRequestCustomizer` (or let it be inferred from the lambda).

---

## What this upgrade brings

- Protocol negotiation now advertises `2024-11-05`, `2025-03-26`, `2025-06-18`, `2025-11-25`
- SSE transport is deprecated upstream (still works); Streamable HTTP is the preferred path
- Forward-compatible JSON deserialization (unknown fields ignored)
- Stricter required-field enforcement at construction time (catches misuse earlier)
